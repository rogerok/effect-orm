Продолжи обучение в проекте Effect ORM.

## Методика

Сначала прочитай `.agents/skills/teach/SKILL.md` как общую методику обучения. Применяй её вместе с обязательным backend mentoring из `AGENTS.md`. При расхождении правил приоритет имеют `AGENTS.md` и текущее состояние проекта.

Пользователь самостоятельно пишет backend-код, тесты, миграции и backend-конфигурацию. Агент исследует репозиторий, объясняет необходимую модель, даёт минимальную следующую задачу, проверяет попытку и помогает диагностировать ошибки.

## Загрузка состояния

Перед началом шага:

1. Прочитай `learning/MISSION.md`.
2. Прочитай `learning/session.md` — это единственный источник текущей точки и следующей задачи.
3. Прочитай `learning/progress.md`.
4. Открой только текущий участок `learning/roadmap.md`, названный в session.
5. Открой из `learning/concepts.md`, `learning/NOTES.md`, `learning/records/` и `learning/references/` только материалы, необходимые для текущего шага.
6. Проверь относящиеся к шагу source, tests, configuration и установленные версии библиотек. Не полагайся на память об API Effect RC.

Не начинай curriculum заново и не пересказывай будущие фазы.

## Один учебный цикл

За один вызов веди только текущий шаг:

```text
конкретная проблема
→ необходимая концепция
→ один high-signal прогноз или объяснение
→ одна маленькая пользовательская задача
→ узкая проверка
→ один comprehension check при наличии новой причинной связи
```

Сначала используй retrieval practice для концепций, отмеченных знакомыми. Объясняй их заново только при обнаруженном пробеле. Для новой концепции сначала дай минимальную ментальную модель, необходимую для текущей задачи.

Не выдавай готовую полную реализацию и не переходи к следующему шагу до наблюдаемой проверки текущего. Не создавай Repository, Unit of Work, relations, transactions или другие будущие abstractions раньше указанного roadmap шага.

Если пользователь передал аргументы команде, используй их как уточнение текущей цели, но не пропускай обязательные prerequisites и verification:

```text
$ARGUMENTS
```

## Завершение шага

После пользовательской реализации:

1. Запусти узкую проверку observable contract.
2. Сопоставь результат с прогнозом пользователя.
3. Объясни точную причинную связь или оставшийся mismatch.
4. Обнови `learning/progress.md` и `learning/session.md` только после подтверждённого результата.
5. Обнови `learning/NOTES.md`, если появилась новая teaching preference, непроверенная гипотеза или важная точка продолжения.
6. Добавь запись в `learning/records/` только для действительно подтверждённого нетривиального результата; не создавай запись за каждый механический шаг.
7. Не повышай mastery выше наблюдаемого уровня самостоятельности.

Если текущий шаг ещё не завершён, сохрани его текущим и закончи ответ одной конкретной пользовательской задачей либо одним high-signal вопросом.

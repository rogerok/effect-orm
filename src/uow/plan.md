Dirty tracking — отслеживание изменений объектов, загруженных через ORM. Пользователь
изменяет объект в памяти, а UnitOfWork при commit определяет, что нужно сохранить в базе.

Для выбранного нами варианта процесс такой.

### 1. Загрузка через findById

В базе находится пользователь:

```ts
{
 id: 1, name
:
 'Anna', age
:
 18
}
```

findById возвращает объект anna. При этом UnitOfWork должен помнить две разные вещи:

- ссылку на сам объект anna, который получит пользователь;
- снимок его исходных значений, независимый от дальнейших мутаций.

Ссылка нужна, чтобы позже увидеть текущее состояние объекта. Снимок нужен, чтобы помнить
исходное состояние.

### 2. Изменение объекта

Пользователь выполняет:

```ts
anna.age = 22;
```

Теперь состояния отличаются:

┌─────────────────┬──────────────┐
│ Где │ Значение age │
├─────────────────┼──────────────┤
│ Объект anna │ 22 │
├─────────────────┼──────────────┤
│ Исходный снимок │ 18 │
├─────────────────┼──────────────┤
│ Строка в базе │ 18 │
└─────────────────┴──────────────┘

Никакой SQL при присваивании не выполняется. Пользователь не вызывает update, register или
markDirty.

### 3. Вызов commit

Пользователь вызывает commit, не передавая объект повторно.

UnitOfWork проверяет отслеживаемые объекты. Для каждого сравнивает текущие значения со
снимком:

- различий нет — UPDATE не нужен;
- различия есть — нужно обновить изменённые поля соответствующей строки.

В нашем примере меняется только age. Имя остаётся прежним. Первичный ключ id определяет,
какую строку обновлять; его изменение здесь не рассматриваем.

Обновления должны выполняться в транзакции вместе с уже зарегистрированными операциями.

### 4. После сохранения

После успешного сохранения новое состояние становится исходным: в снимке теперь тоже age =

22.

Поэтому повторный commit без новых изменений не должен снова обновлять строку. Если
сохранение завершилось ошибкой, нельзя считать изменённые значения успешно сохранёнными и
обновлять снимок.

### Два важных условия

- Повторный findById в том же UnitOfWork не должен заменять исходный снимок текущими
  изменёнными значениями. Иначе ещё не сохранённое изменение потеряется для сравнения.
- Пустая очередь register больше не означает, что сохранять нечего: пользователь мог
  изменить отслеживаемый объект, ничего не регистрируя.

Уже установлено

Ты верно различил новый объект с прежним содержимым, другой литерал и другой диалект. Повторять это не нужно. Сейчас рассматриваем один фиксированный запрос и один диалект: никакого поиска по хешу пока нет.

Два уровня Effect

В установленной версии Effect у cached такая сигнатура:

Effect<A, E, R> → Effect<Effect<A, E, R>>

Внешний эффект создаёт отдельный кешированный эффект. Внутренний эффект вычисляет результат при первом запуске, а при следующих возвращает сохранённый. Создание кеша само по себе ещё не запускает исходное вычисление.

Разделять нужно внутренний эффект. Если снова выполнить внешний эффект, получится другой кеш. Это следует и из реализации cached / cachedWithTTL: состояние создаётся при исполнении внешнего эффекта.

Проследи одно вычисление

Учебный счётчик вместо компилятора. Здесь нет БД и ожидаемых ошибок; Effect.sync откладывает увеличение счётчика до исполнения эффекта.

let calls = 0;
const work = Effect.sync(() => ++calls);
const makeCached = Effect.cached(work);

// Внутри Effect.gen:
const memo = yield* makeCached; // calls = 0
const first = yield* memo;      // first = 1, calls = 1
const second = yield* memo;     // second = 1, calls = 1

makeCached — описание создания кеша. memo — полученный доступ к одному кешу. Два запуска memo обращаются к одному сохранённому результату. Это не глобальное запоминание всех запусков work.

Теперь измени только место создания

Начни мысленно заново: calls = 0, определения work и makeCached те же. До выбора ответа объясни вслух, сколько здесь отдельных кешей.

// Внутри Effect.gen:
const left = yield* makeCached;
const right = yield* makeCached;
yield* left;
yield* left;
yield* right;
yield* right;
// Чему равен calls?

Сначала прогноз и причина, затем проверка.
Разбор для печати и чтения без JavaScript

Ответ: 2. Созданы два независимых кеша, и каждый вычислил work один раз.

Перенеси модель в E2.5

В текущем run каждый запуск вызывает compile, затем driver.executeRaw. Кешировать нужно результат компиляции, а не строки из БД: повторное обращение к БД должно остаться повторным обращением.

Effect.cached не принимает IR или ключ. Поиск нужной записи по содержимому IR — отдельная задача. Для одной записи ты теперь знаешь различие между созданием кеша и повторным использованием.

Следующее действие: объясни агенту, что случится, если при каждом вызове будущего compileCache(ir) заново выполнять Effect.cached, и что должно переживать отдельный вызов. Реализацию ORM пока не пиши.

Завтра без памятки восстанови два уровня: какой эффект создаёт место хранения и какой пользуется им.

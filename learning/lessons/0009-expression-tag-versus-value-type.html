Один _tag.
Разные типы значений.

Научиться объяснять, почему TypeScript различает Expr<number> и Expr<string>, хотя оба могут описывать Literal.

Карта обучения · Знакомая модель AST · Памятка

1. Почему не _tag

Твой прогноз об ошибке типов верен. Но _tag отвечает на вопрос «какой это узел?», а не «какого типа его значение?». Оба объекта ниже — литералы:

{ _tag: 'Literal', value: 18 }
{ _tag: 'Literal', value: '18' }

В чистом IR поле Literal.value объявлено как unknown. После сужения по _tag === 'Literal' оно остаётся unknown: строку от числа этот тег не отличает.

2. Где сохраняется число

В твоём Expr<T> к форме узла добавлен маркер:

declare const Brand: unique symbol;
type Expr<T = unknown> = { readonly [Brand]?: T } & ExprIR;

ExprIR описывает форму узла. [Brand]?: T сохраняет в его типе информацию о типе значения выражения. Это фантомный маркер (phantom brand): текущие конструкторы не создают такое свойство в объекте, но TypeScript учитывает его в типах.

Expr<number> → у маркера тип number
Expr<string> → у маркера тип string

Само имя параметра T ничего не защищает. Оно влияет на совместимость, потому что используется в типе свойства. Это правило структурной совместимости TypeScript.

Знак ? разрешает отсутствие свойства. Он не делает несовместимые объявленные типы этого свойства одинаковыми.

3. Как это помогает between

У типизированного between все три параметра записаны как Expr<T>. В нашем примере TypeScript выводит T = number и отвергает строковую нижнюю границу. Из фактической диагностики установленного компилятора:

TS2345: Expr<string> is not assignable to Expr<number>.
Types of property '[Brand]' are incompatible.

Две разные задачи: _tag выбирает способ обработки узла; T, сохранённый маркером, связывает типы значений аргументов.

Это проверка до исполнения, не runtime-валидатор. Аннотации типов стираются; конструктор сам по себе не проверяет данные из внешнего мира. Расширение до unknown или переход к чистому IR ослабляет эту защиту.

4. Прогноз без правки проекта

Мысленно убери маркер из определения, оставив type Expr<T> = ExprIR. Сигнатуру between не меняй. Сохранится ли ошибка для числового выражения со строковыми границами?

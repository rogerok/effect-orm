Урок 0004 · 10 минут · разделы 2.1–2.5

Четыре разных результата одного запроса

После урока ты сможешь по одной строке кода определить: она строит данные, компилирует их, описывает Effect или действительно выполняет SQL.

Справочник по пайплайну ↗

1. AST — ещё не SQL

between(col("age", "users"), lit(18), lit(65))

Каждый вызов здесь синхронно создаёт обычный объект. Значение описывает условие, но не сравнивает возраст и не знает, существует ли таблица users.

Диагностический вопрос: можно ли выполнить этот код без базы и драйвера? Если да, перед нами построение данных.

2. Compiled — ещё не выполнение

compile(ir, PgDialect)
// → {
//   sql: '... "users"."age" BETWEEN $1 AND $2',
//   params: [18, 65]
// }

Компилятор — интерпретатор AST. Он рекурсивно выбирает SQL-синтаксис, quoting и placeholders. Вызов остаётся чистым: одинаковые ir и dialect дают одинаковый результат без I/O.

Внутренний mutable-массив params не нарушает внешнюю чистоту, пока он создаётся на каждый вызов и не наблюдается до возврата результата.

3. Effect — описание будущего исполнения

const program = run(ir)
// Effect<RawResult, DriverError, Driver>
RawResult
Что программа выдаст при успехе.
DriverError
С какой типизированной ошибкой программа может завершиться.
Driver
Какая зависимость должна присутствовать в Context до запуска.

Вызов run(ir) создаёт ленивое описание. Тело Effect.gen, компиляция и executeRaw начнут выполняться только после запуска Effect runtime.

4. Runtime пересекает границу I/O

const runnable = Effect.provide(program, PgDriverLive)
const result = await Effect.runPromise(runnable)
  1. Runtime начинает EffectДо этой точки SQL не компилировался и драйвер не вызывался.
  2. yield* DriverИз Context извлекается реализация драйвера и её dialect.
  3. compile(ir, driver.dialect)Чистый AST превращается в параметризованный SQL.
  4. yield* driver.executeRaw(...)Драйвер выполняет I/O; успех или DriverError возвращается в Effect.

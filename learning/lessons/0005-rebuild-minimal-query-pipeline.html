Урок 0005 · практика извлечения · разделы 2.1–2.4

Собери минимальный pipeline с пустого файла

Вводная диагностика уже пройдена. Теперь задача не узнать знакомый код, а воспроизвести его устройство без подсматривания.

← Карта обучения · Справочник — открыть только после попытки ↗

Наблюдаемый результат

Создай learning/exercises/0001-minimal-select.ts. Программа должна средствами собственного AST описать запрос:

выбрать id и name
из users
где age больше 18

После компиляции PostgreSQL-диалектом результат обязан быть точным:

{
  sql: 'SELECT "id", "name" FROM "users" WHERE "age" > $1',
  params: [18]
}

Ограничения

  • Не открывай src/compiler/ до первой работающей попытки.
  • Не импортируй готовые IR, constructors или compiler из проекта.
  • Не используй Effect: этот срез заканчивается на чистом { sql, params }.
  • Значение 18 не должно попасть внутрь SQL-строки.
  • Quoting и placeholder должны приходить из маленького объекта dialect, а не быть зашиты по веткам AST.
  • Реализуй только операции, необходимые этому запросу. Не копируй весь язык курса.

Порядок работы

  1. АлгебраВыпиши минимальный словарь операций, встречающихся в целевом запросе.
  2. ASTОпредели readonly runtime-данные и discriminant для каждого варианта.
  3. Smart constructorsСобери целевой запрос без ручного написания вложенных object literals в месте использования.
  4. CompilerРекурсивно получи SQL и накопи параметры в порядке обхода.
  5. ПроверкаСравни точный объект результата, а не только наличие фрагментов строки.
Не исправляй дизайн заранее. Если первая версия кажется примитивной, это нормально. Сначала получи правильный контракт для одного запроса; затем мы изменим требование и увидим, где дизайн сопротивляется расширению.

Самопроверка

В конце файла добавь проверку точного результата через node:assert/strict, затем выполни:

pnpm exec tsx learning/exercises/0001-minimal-select.ts

pnpm exec tsc --noEmit --strict \
  --target ES2022 \
  --module NodeNext \
  --moduleResolution NodeNext \
  learning/exercises/0001-minimal-select.ts

Успех означает одновременно: assertion не падает и TypeScript завершается без ошибки.

После первой попытки

Только после зелёной проверки сравни свою структуру со справочником и текущим src/compiler. Запиши не различия в названиях, а различия в обязанностях: где строятся данные, где выбирается SQL-синтаксис и где накапливаются параметры.

Первичный источник

Если после самостоятельной попытки нужен источник, используй сохранённый курс, разделы 2.1–2.4. Не переходи к 2.5, пока чистый срез не воспроизводится без копирования.

Когда файл проходит обе проверки, сообщи результат. Следующее изменение требования проверит расширяемость AST; затем отдельно восстановим Effect-helper из 2.5. Непонятна граница — спроси агента, указав текущие вход и выход функции.

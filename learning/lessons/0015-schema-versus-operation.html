Effect ORM · урок 0015 · E4.3 порядок вставки

Порядок таблиц знает схема. Таблицу операции знает операция.

topologicalSort и insertOrderEdges уже работают. Чтобы подключить их к commit, нужно понять, какие данные откуда приходят.

5–10 минут · одна модель, три вопроса · backend-код менять не нужно

Карта обучения · Два источника · Модель · Почему не relations · Что меняется в API · Проверка · Саммари · Памятка

Что ты сможешь объяснить

Какие аргументы получает uow.register, что передаётся в Unit of Work один раз и почему commit без таблицы операции не может упорядочить очередь.

1. Два источника данных

commit делает три шага. Первые два используют только схему. Третий использует данные каждой операции.

Схема
Все объекты relations. Из них получаются рёбра и порядок таблиц. Добавление операции в очередь их не меняет.
Операция
Одна таблица, в которую пишет эффект. По ней commit находит позицию операции в порядке таблиц.

2. Модель: зарегистрируй в любом порядке

Нажимай register в произвольном порядке, затем commit. Следи за левой колонкой: она не меняется. Потом включи «старый API» и снова нажми commit.

Схема отвечает «в каком порядке таблицы». Очередь отвечает «какие операции в какую таблицу». Сортировка очереди соединяет эти ответы через одну строку: имя таблицы операции.

3. Почему операции нельзя передать relations

relations(users, …) описывает таблицу-родителя и всех её потомков. У таблицы-потомка вроде posts в нашей схеме может не быть своего объекта relations. 

uow.register(insertPost, userRelations)
// commit прочитает userRelations.table → users
// и поставит вставку поста туда, где должны быть вставки пользователей

Операции нужна не вся карта связей, а одна отметка: «я пишу в posts». Карта связей нужна один раз для всей очереди.

4. Что меняется в API

// Операция несёт свою таблицу
uow.register(posts, insertPost)

// В очереди лежит пара, а не голый эффект
interface PendingOperation {
  readonly table: AnyTableDef
  readonly effect: UoWEffect
}

// Схема попадает в Unit of Work один раз
// (где именно — следующее решение: Layer или commit)
[userRelations, postRelations]

Внутри одной таблицы порядок регистрации сохраняется: Array.prototype.sort стабилен начиная с ES2019 (ECMAScript spec). Две вставки постов выполнятся в том порядке, в котором их зарегистрировали.

5. Проверка понимания

А. В очередь добавили вставку поста 11. Что передаётся в register?

Выбери вариант.

Б. После регистрации поста 11 что изменилось в рёбрах и порядке таблиц?

Выбери вариант.

В. Очередь: post 10, user 7, post 11. Порядок таблиц [users, posts]. В каком порядке выполнятся операции?

Выбери вариант.

Саммари

  1. Схема — все relations. Задаётся один раз. Даёт рёбра (insertOrderEdges) и порядок таблиц (topologicalSort).
  2. Операция — таблица + эффект. Таблица нужна, потому что внутрь Effect заглянуть нельзя.
  3. commit сортирует очередь по порядок.indexOf(op.table), затем исполняет её в транзакции.
  4. Операции одной таблицы сохраняют порядок регистрации: сортировка стабильна.

Основной первоисточник: Martin Fowler — Unit of Work — короткое описание паттерна: Unit of Work собирает изменения и сам решает, как записать их в базу. Алгоритм сортировки: Topological sorting — Kahn's algorithm.

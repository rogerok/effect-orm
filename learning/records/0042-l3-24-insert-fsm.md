# 0042 — L3.24: INSERT без RETURNING, типовое состояние и результат

## Контекст

Первый шаг упражнения E3.3: добавить fluent-интерфейс к существующему INSERT, не переписывая компилятор и драйвер.
Backend-код и тесты написал пользователь с пошаговой помощью наставника.

## Результат

В `src/query/write-builders.ts`:

- `insertInto(table)` создаёт `InsertQueryBuilder<T>` без метода `execute`.
- `values(rows)` принимает `ReadonlyArray<InferInsert<T>>`, вызывает существующий `insert` и возвращает
  `ExecutableInsert<AffectedRows>`.
- `ExecutableInsert.execute` делегирует в `run`; тип результата выражен через `StatementResult<Insert<R>>`.
- `toIR(): Insert<R>` возвращает сохранённое описание запроса. Метод оставлен по явному решению пользователя.

В `src/query/write-builder.test.ts` проверяются точный успешный результат `{ affectedRows: 1 }`, его тип
`{ readonly affectedRows: number }` и отсутствие `execute` в типе начального builder.

## Наблюдаемая проверка

Временный сценарий через полную цепочку builder и фейковый драйвер подтвердил:

- до запуска Effect драйвер не вызывается;
- выполняется один `INSERT INTO "users" ("id", "name") VALUES ($1, $2)` с параметрами `[1, 'a']`;
- при ответе драйвера с `affectedRows: 7` результат равен `{ affectedRows: 7 }`.

Реальная база в этом шаге не использовалась. Временный сценарий запускался через `node` с `tsx` без создания файла.

## Мутационная проверка

Пользователь временно заменил результат `toIR` на копию `stmt` с `returning: '*'`, сохранив тип `Insert<R>`.
Наличие мутации и использование `run(this.toIR())` подтверждены чтением кода. Пользователь прислал ошибку утверждения:

```text
Error: Expected Result.Success value to equal:
Object {
  "affectedRows": 1,
}
```

Сообщение подтверждает, что тест обнаружил мутацию. Фрагмент сообщения не содержит фактического значения и общей
статистики запуска. По коду причина расхождения: `runWithSql` при ненулевом `returning` выбирает `raw.rows`, а фейковый
драйвер возвращает `rows: []`. Проверка типов на мутированном коде агентом не запускалась.

Пользователь восстановил `return this.stmt`; восстановление подтверждено чтением файла. После восстановления агент
выполнил:

- `pnpm check-types` — код `0`;
- `pnpm test src/query/write-builder.test.ts src/query/builder.test.ts` — девять тестов прошли.

## Учебный вывод и границы

Тип результата и значение при исполнении проверяются отдельно: параметр `R` влияет на тип, поле `returning` — на
выбор значения в `runWithSql`. Приведение `as StatementResult<S>` не проверяет соответствие этих двух решений.

Пользователь самостоятельно назвал состояние после `values` как состояние с `execute`. Связь параметра `R` и поля
`returning` объяснена наставником; самостоятельное объяснение пользователя ещё не подтверждено. Уровень освоения
не повышен на основании одного успешного теста.

L3.24 закрыт. Следующий шаг — L3.25: несколько строк, общий список колонок и ошибка при несовпадении набора колонок.

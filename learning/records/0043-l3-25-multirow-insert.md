# 0043 — L3.25: несколько строк INSERT и общий список колонок

## Контекст

Builder уже поддерживал несколько строк через существующий `insert` и `compileInsert`. Пользователь проверял
соответствие значений колонкам, отказ при несовпадении наборов колонок и исполнение на реальной базе.

## Подтверждённое поведение

В `src/query/write-builder.test.ts` пользователь добавил проверки:

- Для `[{ id: 1, name: 'John' }, { name: 'Ann', id: 2 }]` компилятор PostgreSQL формирует
  `INSERT INTO "users" ("id", "name") VALUES ($1, $2), ($3, $4)` с параметрами `[1, 'John', 2, 'Ann']`.
- Если `name` имеет значение по умолчанию и отсутствует во второй строке, типы обеих строк допустимы, но компилятор
  отклоняет разные наборы колонок. `toThrow` проверяет сообщение об этой причине; обычное исключение возникает
  при компиляции, до исполнения SQL.
- Настоящий SQLite в памяти получает две строки через INSERT builder. Проверяются `affectedRows === 2` и точные
  строки, прочитанные через SELECT builder с `ORDER BY id`. Создание таблицы, вставка и чтение используют один слой.

После очистки тест называется `inserts two rows with different property order`, неиспользуемый `ph` удалён,
результат INSERT называется `insertResult`.

## Проверка

После пользовательских изменений агент выполнил:

- `pnpm check-types` — код `0`;
- `pnpm test src/query/write-builder.test.ts src/query/builder.test.ts` — 12 тестов прошли, включая настоящий SQLite.

Отдельный временный запуск существующего компилятора подтвердил: если первая строка перечисляет `name` перед `id`,
SQL-список колонок становится `("name", "id")`, а параметры — `['John', 1, 'Ann', 2]`.

## Причинная связь и уровень самостоятельности

Первый объект определяет общий список колонок. Каждая строка читается по этому списку, независимо от порядка
собственных ключей. Порядок SQL-колонок и параметров может меняться согласованно; сохраняется соответствие значения
его колонке, а не неизменность массива параметров.

Пользователь сначала предсказал порядок значений по ключам каждой строки, затем предположил полную независимость
параметров от порядка ключей. Объяснение и контрпример даны наставником. Самостоятельное объяснение пока не подтверждено;
проверку понимания переносим в последующее повторение, оценку освоения не повышаем.

Практическая часть L3.25 подтверждена. Долг по самостоятельному объяснению сохраняется при переходе к L3.26.

# 0039 — E3.1: `selectAll()` ограничен единственным источником

## Контекст

До этого шага единственным способом задать проекцию был `select(callback)` с явным перечислением колонок. Упражнение
E3.1 добавляет `selectAll()`, но только для запроса без join: после join плоский `SELECT *` возвращает колонки обеих
таблиц, и две колонки `id` не имеют разных имён в результате.

## Результат

```ts
selectAll(
  this: IsSingleSource<S> extends true ? SelectQueryBuilder<S> : never,
): ExecutableQuery<InferRow<S[keyof S]>> {
  return new ExecutableQuery({ ...this.state, columns: '*' });
}
```

Три части решения:

1. `this` parameter объявляет требование к получателю. Проверка выполняется в месте вызова и исчезает при компиляции.
2. `IsSingleSource<S>` вычисляет признак из числа ключей `S`, а не из отдельного поля. Поэтому `where`, `orderBy`,
   `limit` и `offset`, возвращающие `SelectQueryBuilder<S>`, признак сохраняют.
3. Тип строки получается двумя подстановками: `S[keyof S]` даёт единственный `TableDef`, `InferRow` превращает его в
   объект значений.

Вспомогательные типы объявлены рядом с классом:

```ts
type IsUnion<T, U = T> = T extends unknown
  ? [U] extends [T]
    ? false
    : true
  : never;
type IsSingleSource<S> = IsUnion<keyof S> extends true ? false : true;
```

## Проверка

`pnpm check-types` — exit code 0. Остальное проверялось временным скриптом `src/hw/tmp-e31-check.ts`, удалённым после
прогона.

- `selectFrom(users, 'u').selectAll()` → `SELECT * FROM "users" AS "u"`, параметров нет.
- `selectFrom(users, 'u').where(...).selectAll()` → `SELECT * FROM "users" AS "u" WHERE "u"."id" > ?`, параметры `[1]`.
- Реальный прогон на SQLite вернул `[{ id: 1, name: 'Ann' }, { id: 2, name: 'Bob' }]`; выражение
  `rows[0]?.name.toUpperCase()` компилируется, то есть тип строки действительно `{ id: number; name: string }`.
- Вызов после `innerJoin` и после `leftJoin` отклоняется: обе директивы `@ts-expect-error` оказались использованными.
  Текст ошибки — `TS2684: The 'this' context ... is not assignable to method's 'this' of type 'never'`.

Практическая деталь: при ошибке `this` компилятор указывает на начало цепочки вызовов, поэтому `@ts-expect-error`
ставится над первой строкой выражения, а не над `.selectAll()`.

## Что потребовало разбора

Приём с распределением условного типа (`IsUnion`) пользователь не восстановил самостоятельно; конструкция
`this: IsSingleSource<S> extends true ? ... : never` была показана целиком после трёх итераций непонимания. Первая
версия метода имела свободный параметр `<R>`, который не выводился ни из чего: наблюдение показало, что
`selectAll<{ totallyWrong: boolean }>()` компилировался. Вторая версия возвращала `ExecutableQuery<S>`, то есть обещала
строку, состоящую из описания таблицы.

Пользователь сам сформулировал вывод о переносе проверки в компиляцию. Уточнение, добавленное к этой формулировке: тело
метода остаётся runtime-кодом, а гарантия держится на том, что каждый метод согласованно меняет и runtime state, и `S`.
Два уже наблюдавшихся расхождения этой пары — записи 0037 и 0038.

## Границы решения

- Повторный alias схлопывает ключи, поэтому такой билдер считается односточниковым. Это согласуется с решением 0037.
- Проверка держится на literal alias. Если alias когда-нибудь расширится до `string`, `keyof S` станет `string`, а это
  не объединение — ограничение молча ослабнет.

## Защита от регрессии

Пользователь добавил `src/hw/e3-1.ts` с двумя случаями: вызов после `innerJoin` под `@ts-expect-error` и обычный вызов
при одном источнике. Мутационная проверка подтвердила, что директива покрывает именно ограничение: после удаления
`.selectAll()` из цепочки `pnpm check-types` сообщает `TS2578: Unused '@ts-expect-error' directive`.

Не покрыто: вызов после `leftJoin` и вызов после модификатора (`where` перед `selectAll`). Второй случай защищает
выбранный дизайн — признак вычисляется из `keyof S`, поэтому модификаторы его сохраняют; при переходе на отдельный
маркер этот случай перестал бы компилироваться.

# Удерживаемый V8 heap отделён от RSS процесса

Пользователь подтвердил ключевой вывод memory experiment: если после `runFold` достижимый массив всё ещё содержал бы миллион строк, forced GC не смог бы удалить их и вернуть `heapUsed` примерно к исходному уровню. Поэтому `heapUsed` после GC проверяет retention JavaScript-объектов, тогда как рост RSS сам по себе не доказывает утечку: RSS также включает native SQLite, snapshot allocations и страницы, которые allocator ещё не вернул ОС.

**Evidence:** миллионный scan вернул точные count/sum; `heapUsed` после forced GC снизился на 594 792 B, оба heap snapshot созданы, а пользователь правильно ответил на контрпример с достижимым массивом.

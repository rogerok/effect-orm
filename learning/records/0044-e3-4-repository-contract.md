# 0044 — E3.4: Repository проверен через публичный интерфейс

## Контекст

Пользователь реализовал `makeRepository(table)` поверх builder урока 3. Репозиторий предоставляет `findById`, `findBy`,
`findMany`, `save`, `update` и `delete`. После временных сценариев пользователь разрешил создать постоянные тесты.

Проверяемый шов — объект, возвращаемый `makeRepository`. Тесты не обращаются к IR, compiler или внутренним полям
builder. SQLite используется как настоящий адаптер `Driver`.

## Подтверждённое поведение

В `src/query/make-repository.test.ts` закреплены семь контрактов:

- `save` возвращает строку с ключом и SQL DEFAULT, полученными от базы;
- `findById` возвращает строку либо `null`, `findBy` поддерживает несколько условий;
- `findMany` возвращает все совпадения, пустой массив без совпадений и все строки для пустого фильтра;
- значение `null` преобразуется в `IS NULL` и сочетается с другими условиями;
- `update` возвращает изменённую строку, не меняет соседнюю и даёт `NotFoundError` для отсутствующего ключа;
- `delete` возвращает `void`, не затрагивает соседнюю строку и допускает повторное или отсутствующее удаление;
- имя и тип первичного ключа берутся из `_pk`: текстовый `externalId` работает при наличии отдельной колонки `id`;
- таблица без первичного ключа отклоняется через `PrimaryKeyError` при создании репозитория;
- ошибки драйвера сохраняются как `UniqueViolationError`;
- пустой результат INSERT RETURNING считается дефектом `ReturningError`;
- проверки типов запрещают неверный тип ключа, изменение первичного ключа, неверный тип фильтра и INSERT без обязательного
  поля.

## Связанные исправления модели типов

Во время реализации обнаружено структурное столкновение: строка таблицы могла иметь колонку `affectedRows`, поэтому
`R extends AffectedRows` неверно различал счётчик и массив RETURNING. Теперь `InferReturning` вычисляет полный результат
write-запроса, а `StatementResult` извлекает его без повторного структурного ветвления. `InferRow` ограничен строковыми
именами колонок. Старые закомментированные определения удалены после проверки.

## Уровень самостоятельности

Пользователь написал реализацию Repository. Наставник показывал отдельные фрагменты для `Option`, `IS NULL` и условных
типов, диагностировал псевдонимы и модель результата, затем написал постоянные тесты по явному разрешению пользователя.
Основные сценарии E3.4 подтверждены. Самостоятельное восстановление всей реализации без подсказок не проверено, поэтому
уровень владения условными типами и Effect-контрактами не повышается до самостоятельного.

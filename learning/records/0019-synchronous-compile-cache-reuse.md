# Синхронный кеш переиспользует результат по содержимому IR

Пользователь исправил потерю результата `HashMap.set`: общая переменная замыкания объявлена через `let` и получает обновлённую коллекцию. Также убран неиспользуемый IR из параметров фабрики. Сам пользователь отметил, что переприсваивание выглядит непривычно; это ещё не подтверждение уверенного понимания неизменяемых коллекций.

**Evidence:** изолированно исполнена текущая фабрика из `src/compiler/compiler.ts` с настоящим компилятором и счётчиком вызовов. Четыре обращения с литералами 18, 18 (новый объект), 21, 18 (новый объект) вызвали compile дважды; параметры результатов — [18], [18], [21], [18]; повторные обращения вернули прежний объект Compiled. Backend-код преподаватель не менял.

Следующий шаг — заменить сохранение готового Compiled на сохранение кешированного эффекта через Effect.cached. E2.5 ещё не завершено; замера 10 000 обращений нет.

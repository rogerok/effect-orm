# Teaching notes

- Пользователь хочет сначала пройти диагностику ментальной модели, а учебный маршрут строить только по обнаруженным пробелам.
- Чередовать объяснение своими словами, прогноз поведения, чтение существующего кода, небольшую пользовательскую правку и проверку типами/тестами.
- Главный критерий уверенности: пользователь может без копирования заново собрать путь `алгебра → AST → smart constructors → compiler → Effect.run`.
- До завершения этой миссии не использовать материал раздела 2.6 и далее.

## Маршрут после завершённой диагностики

Базовую классификацию `Expr` / `Predicate` / statement, цепочку `AST → Compiled → Effect → I/O` и расширение AST через `Between` пользователь уже прошёл. Не повторять урок 0004 и вводные задания 2.1.

1. С пустого файла собрать минимальный вертикальный срез 2.1–2.4 для одного SELECT: собственные AST, smart constructors, dialect и compiler.
2. Изменить требование и добавить новый узел без подсматривания, чтобы проверить расширяемость и exhaustiveness.
3. Отдельно восстановить `run` из 2.5 по целевому типу и проверить ленивость с fake Driver.
4. Через интервал не меньше суток собрать минимальный путь 2.1–2.5 в новой пустой заготовке и сравнить с текущей реализацией.

На каждом шаге: retrieval practice без кода проекта → прогноз → пользовательская реализация → узкая проверка. Справочник открывать только после первой самостоятельной попытки.

# Teaching notes

- Пользователь хочет сначала пройти диагностику ментальной модели, а учебный маршрут строить только по обнаруженным пробелам.
- Чередовать объяснение своими словами, прогноз поведения, чтение существующего кода, небольшую пользовательскую правку и проверку типами/тестами.
- После установления базовой модели не дробить знакомый TypeScript-синтаксис на отдельные вопросы. Пользователь прямо отметил вопрос про union return type как слишком простой; повышать сложность через вложенные деревья и контрпримеры, которые меняют поведение.
- Главный критерий уверенности: пользователь может без копирования заново собрать путь `алгебра → AST → smart constructors → compiler → Effect.run`.
- До завершения этой миссии не использовать материал раздела 2.6 и далее.

## Последний учебный срез

- [`Урок 0008`](lessons/0008-constant-predicate-boundary.html) — последний практический шаг E2.3: constant folding для `Eq(Literal, Literal)` и граница `WHERE`.
- Пользователь уже реализовал рекурсивный проход многосоставного `And`: каждый ребёнок оптимизируется, `Boolean(true)` отбрасывается, `Boolean(false)` останавливает проход, результат нормализуется по числу детей. Проверка типов и узкие тесты проходили.
- [`Запись 0015`](records/0015-e2-3-explicit-boolean-optimizer-complete.md) фиксирует полный проход с явным `Boolean` и расхождение с исходным acceptance-контрактом курса.
- [`Индекс записей`](records/index.md) связывает результаты 0005–0015 с уроками и справочниками.
- Пользователь сам поставил под сомнение `Eq(lit(1), lit(1)) → null`: объяснять разницу между локальным acceptance-контрактом и глобальной семантической корректностью, не объявлять тест источником истины.
- На уточняющие вопросы отвечать в чате; не переписывать уже созданный урок без явной необходимости или просьбы пользователя.

## Маршрут после завершения E2.3

1. Повторить [урок 0007](lessons/0007-ast-optimizer-from-frontend.html): прочитать `Not(Not(p))` как вложенные JavaScript-объекты и объяснить результат без терминологии компиляторов.
2. Повторить [урок 0006](lessons/0006-e2-3-optimizer-pass.html): восстановить порядок обхода и правила нормализации снизу вверх.
3. Сверить решение с [optimizer reference](references/optimizer-pass.html) и [картой инвариантов](references/0001-predicate-optimizer-invariants.html), отдельно отметив расхождение `Boolean` и `null`.
4. Вернуться к [уроку 0005](lessons/0005-rebuild-minimal-query-pipeline.html) и собрать минимальный вертикальный срез 2.1–2.4, затем отдельно восстановить Effect-helper из 2.5.

На каждом шаге: retrieval practice без кода проекта → прогноз → пользовательская реализация → узкая проверка. Справочник открывать только после первой самостоятельной попытки.

# Teaching notes

- Пользователь хочет сначала пройти диагностику ментальной модели, а учебный маршрут строить только по обнаруженным
  пробелам.
- Чередовать объяснение своими словами, прогноз поведения, чтение существующего кода, небольшую пользовательскую правку
  и проверку типами/тестами.
- После установления базовой модели не дробить знакомый TypeScript-синтаксис на отдельные вопросы. Пользователь прямо
  отметил вопрос про union return type как слишком простой; повышать сложность через вложенные деревья и контрпримеры,
  которые меняют поведение.
- Главный критерий уверенности: пользователь может без копирования заново собрать путь
  `алгебра → AST → smart constructors → compiler → Effect.run`.
- До завершения этой миссии не использовать материал раздела 2.6 и далее.

### Диагностика типизированного Between

- Пользователь самостоятельно заметил необязательность бренда и возможность расширить тип `Expr<T>`; предположил, что
  смешанный вызов может дойти до ошибки в БД. Это основание не повторять вводную про generics, но отдельно разобрать
  совместимость типов и вывод `T`.
- Изолированный запуск установленного `tsc` показал: при `age: Expr<number>` вызов `between(age, lit(18), lit('65'))`
  отклоняется с TS2379. Явный `<number | string>`, первый аргумент `Expr<number | string>` и raw IR-вызов принимаются.
  Объект `{ _tag: 'Literal', value: '65' }` также присваивается `Expr<number>` без бренда. Временные файлы удалены;
  backend не менялся.
- Проверка в изолированной PGlite: `SELECT 40::integer BETWEEN $1 AND $2 AS matches` с `[18, '65']` вернула `true`.
  Строковый параметр не гарантирует ошибку БД: в данном контексте он принят как число.
- Диагностический ответ: пользователь верно предсказал отклонение вызова
  `between(Expr<number>, Expr<string>, Expr<string>)`, но объяснил его через `_tag`. Это обнаруженный пробел, не
  подтверждённое понимание фантомного маркера.
- Подготовлен [урок 0009](lessons/0009-expression-tag-versus-value-type.html)
  и [памятка](references/expression-type-marker.html): `_tag` различает форму узла, `[Brand]?: T` сохраняет тип
  значения. Следующий прогноз — останется ли ошибка, если мысленно убрать маркер и оставить `type Expr<T> = ExprIR`.
  Исправление модели пока не подтверждено ответом; новую запись об освоении не создавать.

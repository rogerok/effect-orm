# Mission: Free/AST-пайплайн запросов до Effect

## Why

Самостоятельно, без копирования из курса, заново собрать в текущем ORM путь `алгебра → чистый AST → smart constructors → компилятор → Effect.run`. Это должно заменить ощущение узнавания кода способностью воспроизвести и объяснить решения перед переходом к разделу 2.6.

## Success looks like

- По пустой заготовке определить алгебру запросов и представить её размеченными объединениями AST.
- Написать нетипизированные smart constructors и объяснить, почему они только строят данные, но не выполняют запрос.
- Реализовать исчерпывающий fold-компилятор, который выдаёт параметризованные `{ sql, params }` с учётом диалекта.
- Связать компиляцию с `Driver` через маленький Effect-helper, сохранив типы результата, ошибки и зависимости.
- Подтвердить собранный пайплайн проверкой типов и поведенческими тестами, затем объяснить, как через него проходит один запрос.

## Constraints

- Главный источник: сохранённая глава «Своя ORM на TypeScript + Effect.ts».
- Рассматривать только разделы 2.1–2.5 включительно.
- Сначала диагностировать ментальную модель; маршрут строить только по обнаруженным пробелам.
- Backend-код и тесты пишет пользователь; преподаватель даёт модель, задания и обратную связь.
- Чередовать объяснение, прогноз, чтение кода, самостоятельную правку и проверку.

## Out of scope

- Типизированный AST и phantom-бренды из раздела 2.6.
- Типизированный `run`, стриминг, N+1/DataLoader и последующие разделы.

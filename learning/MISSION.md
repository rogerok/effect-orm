# Mission: DataLoader один-ко-многим для E2.6

## Why

Самостоятельно реализовать упражнение E2.6: превратить несколько логических запросов `getPostsByUserId(userId)` в один физический SQL `WHERE userId IN (...)`, а затем без потерь раздать каждому запросу его массив постов. Цель — не скопировать пример `getUserById`, а понять границу между `Request`, батч-резолвером и SQL настолько, чтобы воспроизвести решение для связи один-ко-многим.

## Success looks like

- Объяснить разницу между одним логическим `Effect.request` и одним физическим SQL-батчем.
- Описать `GetPostsByUserId` так, чтобы success-типом был массив постов, error-типом — ошибка драйвера, а требованием окружения — `Driver`.
- Собрать все `userId` из `Request.Entry`, выполнить один запрос с `IN (...)` и сгруппировать строки по `userId`.
- Завершить каждый entry ровно один раз, возвращая `[]` пользователю без постов.
- Показать узкой проверкой, что три конкурентных запроса дают правильные три массива и увеличивают счётчик SQL ровно один раз.

## Constraints

- Главные источники: сохранённая глава, публичный API и исходники установленного `effect@4.0.0-rc.108`.
- Сначала диагностировать ментальную модель; маршрут строить только по обнаруженным пробелам.
- Backend-код и тесты пишет пользователь; преподаватель даёт модель, задания и обратную связь.
- Чередовать объяснение, прогноз, самостоятельную правку и наблюдаемую проверку.
- Не полагаться на поведение другой версии Effect или на неподтверждённые утверждения курса.

## Out of scope

- Универсальная DataLoader-абстракция для любых таблиц и связей.
- Repository, Identity Map, Unit of Work, стриминг и упражнения E2.7+.
- Межзапросный или распределённый кеш.

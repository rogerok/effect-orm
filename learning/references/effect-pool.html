Pool: одна страница

Что переиспользуется, кто ждёт и какой Scope за что отвечает.

← Урок 0001 · Механизм Pool · Пулы Node.js

Модель

  1. AcquireСоздать дорогой ресурс и зарегистрировать finalizer.
  2. BorrowВыдать свободный элемент одному fiber.
  3. ReturnЗакрыть scope выдачи; элемент снова свободен.
  4. ReleaseЗакрыть scope пула; запустить finalizer всех элементов.
Пул — не коллекция значений. Это диспетчер ограниченного числа scoped-ресурсов: он хранит их время жизни, выдаёт lease (временное право использования) и создаёт ожидание при исчерпании ёмкости.

Внутреннее состояние

phase: open | closing | closed
resources: Set<A>       // всё созданное
idle: Collection<A>     // доступные элементы
borrowed: Set<A>        // активные lease
creating: number        // async acquire уже зарезервировал capacity
waiters: Queue<Fiber>   // ждут свободный permit

Инварианты

total = idle + borrowed
total + creating ≤ max
idle ∩ borrowed = ∅
checkout → ровно один return или destroy
closed → total = 0 и waiters = 0

Checkout / return

CheckoutВзять idle → иначе создать в пределах max → иначе поставить cancellable waiter.
Return healthyПрямой handoff первому waiter; если очереди нет — перевести в idle.
Return brokenУничтожить, не переиспользовать; при спросе создать замену.
ShutdownНе принимать новые checkout, завершить waiters, закрыть idle, дождаться/пометить borrowed согласно контракту.

Не путать

Semaphore
Ограничивает число входов permits; не владеет экземплярами и их finalizer.
Pool
Владеет identity ресурсов, их созданием, health, idle lifetime и destroy.
Cache
Ищет значения по ключу; lease/return не является главным протоколом.

Три сигнатуры

acquire
  : Effect<DriverImpl, DriverError, Scope>

Pool.make({ acquire, size })
  : Effect<Pool<DriverImpl, DriverError>, never, Scope>

Pool.get(pool)
  : Effect<DriverImpl, DriverError, Scope>
AЭлемент пула: здесь DriverImpl.
EОшибка создания элемента; get может её вернуть.
ScopeТребование времени жизни. Для make — жизнь пула; для get — жизнь одной выдачи.

Два scope

Scope пула
Обычно равен времени жизни Layer или приложения. Закрытие завершает пул и освобождает физические ресурсы.
Scope выдачи
Равен одной работе с элементом: запросу или транзакции. Закрытие возвращает элемент в пул, но не закрывает его.

Фиксированный размер

  • size задаёт фиксированное число элементов: в реализации этой версии min = max = size.
  • concurrency задаёт число одновременных выдач одного элемента; по умолчанию 1.
  • Если все разрешения заняты, Pool.get ждёт; это backpressure — давление назад на вызывающий код.
  • invalidate(pool, item) исключает именно тот объект по строгому равенству и позволяет создать замену.

Что называют pool в Node.js

libuv thread pool
Переиспользует native worker threads; в очереди стоят fs, часть crypto, dns.lookup, zlib.
Worker pool
Переиспользует worker_threads; в очереди стоят CPU-задачи приложения.
http.Agent
Переиспользует TCP/TLS sockets по host/port; в очереди стоят HTTP requests сверх maxSockets.
pg.Pool
Переиспользует PostgreSQL Client/session; в очереди стоят checkout/query.
Buffer pool
Раздаёт slices заранее выделенной памяти; явного lease/return нет.

PGlite: не обычный connection pool

Сетевой PostgreSQL
size: N обычно означает N независимых серверных соединений и потенциальный параллелизм.
Один PGlite
Официально имеет одно exclusive connection. Пул размера 1 может управлять lifetime и admission control, но не добавляет database parallelism.
Текущий make()
Каждый вызов делает PGlite.create(options). Поэтому Pool.make({ acquire: make(options), size: N }) означает до N экземпляров PGlite/WASM, а не N соединений с одним экземпляром.
Главная ловушка E1.8: взять один элемент через Pool.get при сборке Layer и держать его до остановки приложения. Тогда остальные элементы никогда не обслужат запросы; пул существует только формально.

Проверка дизайна

  1. Что именно дорого создаёт acquire?
  2. Какая операция является одной выдачей?
  3. Где закрывается scope этой выдачи при success, failure и interruption?
  4. Что физически означает size > 1 для выбранного ресурса?
  5. Доказывает ли тест ожидание и последующее переиспользование одного и того же экземпляра?

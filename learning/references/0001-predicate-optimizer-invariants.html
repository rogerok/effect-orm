Главный контракт

Сохранение смысла: исходный и новый предикаты должны пропускать одно и то же множество строк. Форма AST может измениться; наблюдаемое поведение запроса — нет.

  • Входной AST не мутируется.
  • Каждый вложенный Predicate сначала проходит рекурсивную оптимизацию.
  • После обработки детей родитель повторно нормализуется.
  • Boolean(true) — постоянная истина внутри AST; на границе where? она удаляется структурно.

Карта констант

Постоянный TRUE
Boolean(true) внутри AST; на границе where? такой результат удаляет свойство where.
Постоянный FALSE
Boolean(false), включая результат пустого Or(); компилируется в SQL FALSE.
SQL UNKNOWN
Возникает при обычных сравнениях с NULL. Это третье значение, не JavaScript false.

Контекст имеет значение

p AND TRUE  → p
p OR  TRUE  → TRUE
NOT TRUE    → FALSE

Поэтому нельзя механически «выкидывать Boolean(true)» из любого списка детей. В And это корректно; в Or такой ребёнок делает весь результат истинным.

Порядок обхода

  1. Распознать вариантNarrowing по полю _tag.
  2. Обработать детейРекурсивно построить новые узлы или константы.
  3. Нормализовать родителяПрименить правило по числу и значениям детей.
  4. Вернуть новый результатНе присваивать в поля исходного AST.

Проверки, которые ловят реальные ошибки

  • Вложенность: Not(Not(And(p))) → p.
  • Потеря ребёнка: And(p, q) сохраняет оба условия.
  • Постоянная истина: Eq(lit(1), lit(1)) → Boolean(true) в текущей реализации.
  • Граница запроса: Boolean(true) в where становится отсутствующим свойством where.
  • Неизменность: входной объект после вызова структурно прежний.

Request batching:
один-ко-многим

Сжатая карта контракта, алгоритма и проверок для getPostsByUserId.

Карта обучения · Урок 0011

Типы

Payload
{ readonly userId: number }
Success
ReadonlyArray<Post> — массив для одного userId, включая [].
Error
DriverError — общий SQL действительно завершился ошибкой.
Services
Driver — зависимость сохраняется в типе request и доступна resolver через entry.context.
Resolver input
Непустой массив Request.Entry<GetPostsByUserId>.

Пайплайн

entries
  → userIds
  → один SELECT ... WHERE userId IN (...)
  → плоские Post rows
  → Map<userId, Post[]>
  → complete каждого entry своей группой или []

Инварианты

  • Один entry соответствует одному логическому результату, а не всему SQL-батчу.
  • Одна строка SQL добавляется ровно в одну группу по её userId.
  • Порядок entry не обязан совпадать с порядком строк SQL; раздача идёт по ключу.
  • Пользователь без постов получает успешный [], не null и не ошибку.
  • Каждый принятый entry завершается ровно один раз.
  • Ошибка SQL остаётся typed failure; её нельзя маскировать пустыми массивами.

План группировки

  1. Создать пустой индекс Map<number, Post[]>.
  2. Для каждой строки получить текущую группу по row.userId.
  3. Если группы нет — создать её; затем добавить строку.
  4. При раздаче читать по entry.request.userId с fallback [].

Не создавать результат только из строк SQL. Тогда userId без строк исчезнет из индекса. Полный набор ожидаемых ответов задают entries, а строки лишь наполняют некоторые группы.

Когда возникает один batch

КомпозицияНаблюдаемое поведение на rc.108
Effect.forEach(..., { concurrency: "unbounded" })Request создаются до запуска resolver и встречаются в одном batch.
Последовательные yield*Первый request ждёт resolver; следующий появляется позже и попадает в новый batch.
Одинаковые ключи [1, 1, 2]Resolver получает [1, 1, 2]; автоматической дедупликации в текущей RC нет.

Минимальная проверка контракта

  • Запросить userId 1, 2, 3 конкурентно.
  • Подготовить два поста для 1, ноль для 2, один для 3.
  • Проверить точные три массива, включая [] для 2.
  • Проверить queryCount === 1.
  • Отдельно убедиться, что SQL содержит IN и все параметры.

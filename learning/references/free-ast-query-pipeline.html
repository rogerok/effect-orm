Справочник · разделы 2.1–2.5

От значения AST до выполнения SQL

Карта четырёх границ: что является данными, что преобразованием, что описанием эффекта и что реальным вводом-выводом.

Главный маршрут

smart constructors
      │ создают
      ▼
IR / AST ── compile(ir, dialect) ──▶ { sql, params }
                                           │
                                           │ run(ir) описывает
                                           ▼
                          Effect<RawResult, DriverError, Driver>
                                           │
                                           │ Effect runtime + Driver Layer
                                           ▼
                                  driver.executeRaw(...)
Алгебра
Словарь языка: Expr, Predicate, statement. Определяет, что можно выразить, но ничего не выполняет.
Чистый AST
Readonly runtime-данные с discriminant _tag. Не содержит драйвер, Effect и методы исполнения.
Smart constructors
Удобно и единообразно создают корректную форму узлов. Не компилируют и не обращаются к базе.
Fold-компилятор
Исчерпывающе обходит AST и возвращает { sql, params }. Dialect отвечает за quoting и placeholders.
Effect-helper
Получает Driver из Context, компилирует IR и описывает вызов executeRaw. Сам вызов run(ir) программу не запускает.

Инварианты

  • Идентификаторы проходят через dialect.quoteIdentifier.
  • Литералы проходят через compileExpr и попадают в params, а не интерполируются в SQL.
  • Порядок рекурсивного обхода определяет порядок placeholders и элементов params.
  • Match.exhaustive ловит отсутствующий case, но не доказывает корректность SQL для существующего case.
  • Поведенческий тест сравнивает и точный SQL, и точный массив параметров.

Тип как карта границы

compileIR × Dialect → Compiled
runIR → Effect<RawResult, DriverError, Driver>

У compile нет ошибки драйвера и требования Driver: это чистое преобразование. У run они видны в типе, потому что программа пересекает границу внешнего мира.

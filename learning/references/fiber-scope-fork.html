Четыре роли

Effect
Описание вычисления; само себя не запускает.
Fiber
Живое исполнение Effect; единица конкурентности.
Scheduler
Возобновляет runnable fibers; suspended fibers CPU не получают.
Scope
Граница lifetime; при закрытии запускает зарегистрированные finalizers.

Алгоритм выбора

  1. Результат B зависит от A? Используй обычный yield* A.
  2. Нужны результаты всех независимых работ? Используй Effect.all с ограничением concurrency.
  3. Нужен handle для join/await/interrupt? Используй forkChild.
  4. Работа должна принадлежать текущему resource lifetime? Используй forkScoped.
  5. Есть конкретный внешний Scope-владелец? Используй forkIn.
  6. Работа обязана пережить родителя? Только тогда рассматривай forkDetach и явно проектируй shutdown/error reporting.

Матрица fork

forkChildOwner: parent fiber. Parent завершился → child interrupted. Возвращает Fiber handle.
forkScopedOwner: текущий Scope. Scope закрылся → fiber interrupted.
forkInOwner: переданный Scope. Удобен, когда scope выбирается явно.
forkDetachOwner: global Scope. Переживает parent; повышенный риск утечки и потерянной ошибки.
В этой версии общего Effect.fork нет. Старые примеры сверяй с установленными сигнатурами; стандартный structured вариант здесь — forkChild.

Управление Fiber

joinДождаться и распространить success/failure/interruption в текущую fiber.
awaitДождаться полного Exit как значения; разобрать результат самостоятельно.
interruptПослать interruption и дождаться завершения cleanup.

sleep

Effect.sleep(duration) приостанавливает текущую fiber, не блокируя JavaScript thread. Он полезен для настоящих задержек, retry/backoff, heartbeat и детерминированного моделирования latency. Он вреден как попытка «подождать, пока race condition сам разрешится».

Pool: две границы

Pool Scope
Жизнь всего пула; closing физически releases созданные ресурсы.
Checkout Scope
Жизнь одной выдачи; closing возвращает ресурс в pool.
Все permits заняты
Pool.get приостанавливает вызывающую fiber до освобождения permit.

Три вопроса при чтении кода

  1. Какая fiber сейчас running, а какая suspended — и на каком событии?
  2. Кто owner каждой дочерней fiber и какой момент прерывает её?
  3. В каком Scope зарегистрирован finalizer ресурса и что именно он делает: return или release?
